# 库存可视化看板与保护新增数量

## 界面

`/app/dashboard` 顶部显示异动趋势、加仓 Top5、减仓 Top5。日期、监控范围、近 3 / 7 日同步作用于三个模块。排行按件数降序，同件数按账号数及稳定饰品键排序；账号链接进入库存，超过三个账号时折叠其余明细。原有每日筛选、变化表、诊断在「每日变化明细」中保留。

不增加价格、收益预测、外部图表依赖或额外供应商调用。明暗主题与手机单列布局沿用平台风格。

## 统计

新增 `GET /api/dashboard/overview?date=YYYY-MM-DD&days=7&scope=mine`。支持 3 / 7 日；结束日期限现有八日日报保留范围。时间按北京时间。

趋势按 DailyObservation 中相邻自然日的有效对比汇总，仅接纳 `status=ready`、`report.comparable=true`、`change.verified=true`。不完整、缓存、身份未知、不同来源口径、缺基线不作为确认的加减仓。这里的加减仓是已校验库存增加/减少，不确认真实买卖或存入组件。

没有可对比账号的日期返回 null，图表留空、折线断开；已校验且无变化返回 0。部分账号可对比时只累加已校验部分，悬停或键盘聚焦日期显示可对比账号数/总账号数。周期累加的每个账号仅计数一次。

持有量按该账号周期内最后一份完整日报的饰品数量，不把多天数量相加；末次日报不完整时显示未知。时间在持有量提示中提供。排行榜和趋势不受下方明细的搜索、分页门槛影响。

普通用户仅自己的订阅，管理员可选全部目标；到期冻结截止时间应用于查询，过期账号拒绝；API `Cache-Control: no-store, private`，`Vary: Cookie`。API 不返回内部 asset id、来源诊断或其他账号订阅备注。

## 库存卡片

`protected_additions` 的 "7" / "1" 统计最新完整保护分区相对于 7 / 1 个北京时间自然日前末次完整保护分区的按资产正向数量增量，仅计交易保护物品。缺基线返回 null，UI 为 —；普通库存变化不计入、减少不抵消新增。同来源口径对比，旧记录不回退。

## 验证与发布

- Python 全量 unittest；新增趋势/排行测试覆盖权限、周期、持有量、缺失/零、重复账号、冻结和 API 缓存。
- `node tests/test_dashboard_overview_js.js` 覆盖缺口断线、已知零、空态、转义、链接、未知数量和清除。
- 浏览器验收近 3/7 日、账号展开、键盘日期提示、明暗主题、手机布局和无数据状态。
- 合并保护新增功能一并发布，不迁移数据库、不改扫描频率；使用 `deploy/release.sh <archive> <commit> --no-migrations` 备份、切换并验收。
- 回滚仅切代码至发布前版本，生产数据库不回退；恢复源码与哈希在独立副本演练。
