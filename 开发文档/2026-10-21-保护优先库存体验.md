# 保护优先库存体验（api_preferred_v2）

## 数据规则
- 每次查询先调用 Steamwebapi 保护分区，成功立即落库，再调用普通分区。
- 仅普通 API 分区异常时访问 Steam 公开 context 2；真实 assetid、逐页验证、公开资产不推断交易保护。
- Steam 部分可见结果可替换普通展示分区，不与历史取并集，不构成完整快照；零库存须有明确证据。
- 同轮两 API 分区完整成功才产生完整基线。旧 api_only_v1 与 v2 不跨口径计算变化。
- 即时查询可保留一小时内上次成功分区与原时间；监控分区独立选择最近成功记录。
- 历史常规保留 8 天，最新成功分区、最近完整展示记录及冻结视图依赖记录作为例外保留，直到被替代。
- 名称修复保留来源元数据并重新构建分区展示，不引入历史资产。

## 权限与接口
- 有效管理员且用户名精确为 cs2inventory_admin 才能主动查询、手动扫描、查看查询历史和诊断。
- bootstrap.user.can_query_inventory 驱动入口展示；后端 super_admin_required 独立校验。
- POST /api/admin/query 兼容单条；POST /api/admin/queries 接收 {items:[{steamid,alias}]}。
- 每批最多 20 个不同 SteamID，全部验证后入队；返回 items 的 job_id、target_id、reused，及 estimated_requests、credits_per_request。
- GET /api/admin/queries 分页读取主动查询历史；GET /api/jobs/:id 对手动/即时任务收紧权限，过期即时结果返回 410。
- SQLite 写事务覆盖活动任务检查和插入，跨进程去重；有监控目标复用持久任务，无监控目标不自动订阅。
- 单件公开结构仍为 name/count/is_trade_protected。inventory_sections 保存独立 items/total_items/updated_at；sections_same_complete_round 仅为展示层合并依据。

## 产品与费用
- 库存查询、订阅管理、实时查询、查询历史独立入口；详情分库存、变化、历史，普通响应不含诊断。
- 同名物品仅在同轮完整结果中合并，展示总数及保护子数量；保护筛选仅显示保护数量。
- 按实际 API HTTP 尝试数计费，公开 Steam 请求不计 API credits，公开兜底前先提交已发生的付费账目。
- 北京时间 08:00/20:00 与双工作线程不变；配额只预警不停扫；不自动全量重扫。
