# API 额度与容量

- Inventory Small 专用限额为每分钟 20 次、每日 5,000 credits、每账期 150,000 credits；应用继续使用每分钟 18 次的全局 Inventory 请求节流。
- 深度扫描基准为 7 次 SteamWebAPI 请求：normal 1、trading 3、mode1 1、parse1 2。供应商实际按参数组合扣 2–3 credits，应用按每次 3 credits 保守记账；分页、重试和失败尝试均纳入统计，Steam 官方公开库存请求不计入供应商 Inventory 用量。
- 定时扫描每日 6 轮（北京时间 00/04/08/12/16/20 点整点触发，槽键 `{日期}-R0..R5`，通知延迟上限 4 小时）。其中 R2 槽（08:00 窗口）为深度轮（每目标 7 请求多源交叉验证），其余 5 轮为轻量轮：每目标一次单库存端点请求（`parse=1` + `try_first_seven_days_blocked_items=1` + `no_cache=1`），可直接发现处于交易保护中的新获得物品，叠加 Steam 官方公开接口交叉验证；单库存端点失败时按任务隔离降级（coverage=degraded），不阻塞组内其余任务。
- 轻量轮能力边界：单库存端点携带 `parse=1` 与 `try_first_seven_days_blocked_items=1`，无需登录态即可返回交易保护中的新物品，并将 `tradeprotectedmaxdays` 解析为保护截止时间上界；保护物品知识由每日深度轮（R2）与观测缓存（10 天）交叉刷新。
- 100 个目标每天用量约为：深度轮 100×21 = 2,100 credits，轻量轮 5×100×3 = 1,500 credits，合计约 3,600 credits/天、约 111,600 credits/账期（31 天），账期余量约 38,000；首次扫描、管理员任务与超大库存分页继续使用该余量。100 是容量参考值，不是新增目标的硬上限。
- 每日与账期限额、30,000 警戒余额和 15,000 严重警戒余额均只用于观测。任何预警级别都不阻止定时、首次、手动或即时扫描，供应商硬限额由上游执行。
- 管理员概览显示本地保守用量、估算余额、预警级别及最近一次供应商账户用量；界面明确标记“仅预警，不停扫”。
- 每用户正式监控限额是独立硬限制，按该用户的 `subscriptions` 数量计算；共享目标也占每个用户一个名额。管理员下调额度不删除现有数据，只阻止新增。
- 定时批次只覆盖至少有一个有效正式、永久、内部或管理员订阅者的目标；公开试用与一次性试用扫描分支已经移除。
- Worker 同时扫描两个目标（或两个批量组，每组最多 20 个 SteamID 在途），全局限制为每分钟 18 次请求。
- Profile 仅在首次添加及七天后刷新昵称时调用，使用独立额度。
